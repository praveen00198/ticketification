# Ticket Storage Architecture — Forensic Audit Report

> **Date**: 2026-09-07
> **Auditor**: Antigravity Agent
> **Scope**: Complete trace of ticket generation, storage, and download pipeline

---

## 1. Executive Summary

The application's ticket generation pipeline has **never actually uploaded ticket assets to Supabase Storage in production**. The `assetUrl` stored in PostgreSQL is a Render filesystem URL (`https://ticketification.onrender.com/uploads/tickets/ticket-GAN-00001.svg`), generated by hardcoded logic in `ticket-image.service.ts`. The Supabase Storage upload path exists in code but **silently fails and is swallowed**, allowing the system to report ticket generation as "successful" even though the canonical storage location (Supabase Storage) was never used.

## 2. Current Architecture (What Actually Happens Today)

```
Frontend (Vercel)
   │  POST /api/tickets/events/:eventId/generate
   ▼
Backend (Render)
   │
   ▼
TicketController.generateTickets()
   │
   ▼
TicketService.generateTicketsForEvent()
   │
   ├─→ QrService.generateQrDataUrl()           ← Generates QR data URL
   │
   ├─→ TicketImageService.buildSvg()            ← Builds SVG string in memory
   │
   ├─→ TicketImageService.generateTicketImage() ← THE PROBLEM IS HERE
   │     │
   │     ├─→ fs.writeFileSync(filePath, svg)    ← Writes to Render /uploads/tickets/
   │     │
   │     └─→ Returns { filePath, publicUrl }
   │              │
   │              └── publicUrl = "https://ticketification.onrender.com/uploads/tickets/ticket-GAN-00001.svg"
   │                  ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   │                  THIS IS THE ROOT CAUSE — hardcoded Render URL generated BEFORE upload attempt
   │
   ├─→ ticketRecord.assetPath = filePath        ← Local disk path
   │   ticketRecord.assetUrl  = publicUrl       ← Render URL set as DEFAULT
   │
   ├─→ StorageService.uploadTicketImage()       ← ATTEMPTED upload to Supabase
   │     │
   │     ├── If success: overwrite assetUrl with Supabase CDN URL
   │     └── If failure: catch → console.warn → CONTINUE (error swallowed!)
   │                     ^^^^^^^^^^^^^^^^^^^^^^^^
   │                     TICKET STILL INSERTED WITH RENDER URL
   │
   └─→ TicketRepository.createMany()            ← Inserts ticket row with whatever assetUrl survived
         │
         └── assetUrl = Render URL (if upload failed or was never configured)
```

### Why Supabase Storage Upload Actually Fails

Tracing the initialization chain:

1. `env.ts` loads `supabaseServiceRoleKey`
2. `supabase.ts` creates `supabaseAdmin` — if key empty, `supabaseAdmin = null`
3. `supabase-storage.service.ts` checks `isConfigured()` → returns `false` if `supabaseAdmin` is null
4. `ticket.service.ts` checks `if (isStorageConfigured)` — **skips entire upload block silently**
5. Ticket record inserted with Render `/uploads/` URL as `assetUrl`

**Even when Supabase IS configured**, upload can fail because:
- `ensureBucket()` silently catches errors
- `uploadTicketImage()` returns `null` on failure
- Calling code treats `null` return as "no change" and keeps Render URL

## 4. Root Cause Analysis

### Primary Root Cause
`ticket-image.service.ts` lines 196-222: The `generateTicketImage()` method:
1. **Writes SVG to Render local filesystem** (`fs.writeFileSync`) — line 209
2. **Constructs hardcoded Render URL** as `publicUrl` — lines 215-219
3. **Returns Render URL as canonical asset URL** — line 221

## 6. Recommended Fixes

### Fix 1: Refactor `generateTicketImage()` — no disk writes, no Render URLs
- Remove `fs.writeFileSync()`
- Remove Render URL construction
- Return `{ svg: string, imageBase64: string }` only

### Fix 2: Fail ticket generation if Supabase Storage upload fails
- Upload SVG to Supabase Storage FIRST
- If upload fails → throw error, do NOT insert ticket record
- If upload succeeds → set `assetUrl` = Supabase CDN URL, `assetPath` = storage path
- THEN insert ticket record

### Fix 3: Remove `/uploads/` static serving from app.ts
- Remove on-demand handler (lines 53-99)
- Remove `express.static` for uploads (line 110)
- Add download endpoint via Supabase Storage

### Fix 4: Fix client URL handling
- If `assetUrl` contains `supabase.co`, use it directly
- Remove `/uploads/` path transformation logic

### Fix 5: Use deterministic, non-token storage paths
Change from: `tickets/<eventId>/<verificationToken>.svg`
To: `events/<eventId>/tickets/<ticketId>.svg`

### Fix 6: Migration for existing tickets
- Query tickets with Render URLs
- Regenerate SVGs, upload to Supabase, update DB

## 8. Database Assessment

Current `tickets` table has:
- `asset_path TEXT` — will store Supabase storage path
- `asset_url TEXT` — will store Supabase public URL

This is sufficient. No separate `ticket_assets` table required for 1:1 relationship.
